# Riverbend：从可运行工程到完整小游戏的完成计划

规划角色：GPT-6.1；日期：2026-11-05。目标是把现有八关桥梁游戏打磨成有开端、递进、结局和重玩理由的有限成品，保留英文游戏界面。用户说的“像 4399”在这里指打开就能玩、规则清楚、反馈及时、能够完整通关的小游戏体验，不指门户站，也不授权复制其他游戏。

本轮只交付规划。下述“应实现”都不是已完成承诺。此审计阅读了当前工作树的 PROJECT_STATUS、README、index.html、styles.css、app.js、engine.js、levels.js、v0.5 教学设计和设计复盘，补查了 content.js 和 package.json。没有运行浏览器、没有进行真人试玩、没有重新执行测试；既有测试记录属于项目历史证据，不是本轮新测结果。

需求来源需分清：用户已确认的是完整小游戏体验、6.1 规划/提示词优化→5.6-sol 细化→6.1 验收的顺序，以及先规划而不擅自全面改游戏。英文界面、八关桥梁、菜单与 About 等是现有项目已确认方向。本计划提出的路线可视化、首入任务形式、切片选择、屏幕矩阵和具体门槛是规划建议，供下阶段执行与验收采用，不冒称用户逐项指定。主代理将新增权威版本提示词并给旧文件添加被替代指引，保留旧稿内容，不直接抹掉历史。

补充现场证据（由主代理 CUA 截图检查转交，非本规划者直接试玩）：默认约 319 px 宽的内嵌浏览器中，第一关顶部导航出现右侧 About 被挤出，施工区与 dock 占用明显；选关目前是卡片列表，没有社区路线地图。这里只证明该尺寸下的界面问题及地图未实现，不证明全部设备不可用或核心玩法无趣。窄幅嵌入应加入验收压力场景；先修可操作性，再判断是否建议放大面板或横屏。

## 1. 现状判断：不是从零，也不能靠“再多加几关”完成

已存在的产品骨架：Phaser 3.90.0、独立固定步长轴向求解器、八关与 Free Build、四格开场、实际操作训练、材料限额、编辑/测试分离、撤销重做、拉压与失效反馈、Notebook、保存迁移、离线打包和自动化测试。应先保存这套能力，再补齐体验闭环。

| 可由源码证实的现象 | 可能产生的 demo 感及根因 | 处理及核验 |
| --- | --- | --- |
| levels.js 的八关有跨度、载荷、材料、桥墩差异，但参考桥统一走 starter() 的三角桁架生成器 | 有机制变化，仍可能被同一构形套路覆盖；“不同参数”未必等于“不同决策” | 每关写一个独立的决策问题与失败样例；用跨关策略迁移审计检验，不靠改标题 |
| app.js experimentResult() 主要写 completed 布尔值，再拼接 C.transition 文案；最终结束是通用 modal | 世界变化的主体仍是标记和文字，配送利害未充分进入可见场景 | 将社区配送后的状态映射到地图/场景小变化，最终呈现八次贡献与玩家证据 |
| index.html 结果区域先列 Edit design，再列 Compare、Reference、Next；app.js feedback() 控制下一关显示 | 成功后下一步与失败后下一步共用信息层级；可能削弱节奏 | 成功主行动 Next，失败主行动 Edit；保留次行动与证据入口，实际观察是否误触 |
| enter() 不自动呈现新任务；next 点击直接 enter()；showTask() 可由 Task 按钮主动打开 | 新约束可能要玩家自行发现，下一关像“换数字的编辑器” | 首次进入关卡呈现可快速跳过的短任务卡：交付对象、此次新约束、目标；重访不重复打断 |
| Notebook 用一个长 modal 拼接可选预测、比较表、最近八条测试和反思 | 完整功能可能挤成工作表；玩家知道“有记录”却不理解如何用证据改桥 | 结果先给一条现场证据和一个可行动问题；Notebook 保留深入对照，默认先露最新两案 |
| app.js 同时维护 screen/mode/training/sandbox/story/dialog 等状态，且承担编辑命令、证据与模板拼接；CSS 有多个尺寸断点 | 功能并非缺失，但继续堆叠容易出现遮挡和状态回退缺陷 | 先写合法状态/返回表，再按需要小步拆状态与视图；不以重写框架为目标 |
| engine.js 已有分关背景缓存、支座标记、断裂效果、缆索松弛、成功粒子与声音 | 不能声称“没有美术/没有反馈”；是否一致、清晰、克制仍需实画面验证 | 建立全流程截图清单和动效预算，优先增强与约束/配送有关的视觉反馈 |
| 教学目标、模型边界主要在 About/Help 和文档；预测、反思不自动评分 | 玩法完成与学习解释之间可能有断点 | 在关键关插入短观察邀请，不用必填作文或正确答案锁住主线 |

“显得单调”“难以上手”“遮挡”目前都是待验证风险，不是已经发生的用户测试结论。不能把本表转换成未经检查的 bug 列表。

## 2. 保留、定向重构、淘汰

- 保留：桥梁主题、英文 UI、完整主菜单、八关总量、自由搭建、多解、无次数惩罚、Phaser 与独立求解器、真实桥墩、材料角色、测试副本、Notebook 的同条件比较、旧存档迁移、沙盒隔离、本地离线交付、原始素材与来源记录。
- 定向重构：首入任务和成功/失败层级；社区路线与持久后果；关卡决策差异；参考桥的展示解释；Notebook 的渐进披露；跨屏幕状态一致性；确有耦合导致的问题才拆 app.js。所有重构先保住现有行为与存档。
- 淘汰：过期的“尚未编程/先做 MVP/只有四关”提示词；用更多弹窗和学术名词冒充教学；以八个关名代替八种决策；用万能参考桥复制完成整条主线；速度/失败次数排行榜；仅截图首页就宣布成品；只过自动测试就声称好玩或学会。
- 暂不做：账户、联网排行、多人、关卡编辑器、商业化、随机无限关、刚体轮胎接触重写、逼真工程安全计算、门户聚合、语音对话树。新增这些会转移完成现有游戏的工作。

## 3. 成品范围与目标体验

交付一款有限的单机小游戏：八关线性主线＋独立沙盒＋证据记录＋可见路线结局。11–14 岁、有成人可引导是现有设计假设；45–75 分钟也是待测目标，不能作为实测时长宣传。桌面鼠标/键盘为主要验收面，平板触控为第二验收面；窄屏提供清楚可操作的自适应或旋转建议，不把“CSS 能缩”当作触控可用。

玩家体验应当是：“我知道社区需要什么，能用自己的桥试一个想法；失败告诉我哪里值得改；不同路段逼我换思路；我看到连接完成；最后能回顾自己的设计并选择继续改进。”

约束总量：只维护八关；每关一个主要新决策；每关一条开场短任务、一条可见配送后果、两级可选提示、至少两个可行设计及有解释的失败样例；全线一个统一结局；沙盒沿用现有四档载荷。剧情不扩张为分支对话系统。

## 4. 核心循环、MDA 与教学证据

单关循环：看到任务和约束 → 提出想法（预测可选）→ 自由搭建 → 运行/观察 → 定位一条证据 → 修改一项主要结构选择 → 相同条件复测 → 配送成功 → 世界改变/进入下一关。首次通关允许直接推进，比较和材料优化提供重玩目标，不用重复实验硬性拖时长。

| Mechanics（实际规则） | Dynamics（要产生的行为） | Aesthetics（目标感受） | 教学落点及证据 |
| --- | --- | --- | --- |
| 可逆构件编辑、材料库存、固定支座 | 主动试设计而非猜唯一形状 | 掌控、创造 | 几何/材料选择，保留设计快照 |
| 自重、移动载荷、拉压/松弛/首断可视化 | 看结果后定位载荷路径 | 好奇、有因可查的挫折 | 理解与分析；指出具体构件和测量 |
| 同条件两案比较、成本奖励 | 控制变化、以证据迭代 | 改进的满足感 | 评价；主张—证据—推理，不把相关当因果 |
| 新支座、无支座、材料角色、重载 | 将旧经验转用于新约束 | 能力增长 | 应用/迁移；新条件下的新方案 |
| 社区配送和路线持久变化 | 关心结果、愿意完成旅程 | 责任、完成感 | 有意义的情境，不冒充概念掌握分数 |

5E 的 Engage/Explore/Explain/Elaborate/Evaluate 要落在上述行动中，About 只负责介绍。每次解释邀请最多一个短问题，允许跳过；教师可选 Notebook 两案做口头评估。通关、反思字数、参考桥使用量都不能单独判定学习成效。

## 5. 八关的差异必须成为玩家决策

下表是内容生产规格，不是宣称目前均已实现。先保留现有数值；只有决策审计证明无法成立时才改库存/几何，并重新审计全部受影响设计。

| 关 | 玩家必须重新考虑什么 | 任务/失败反馈重点 | 过关后的可见后果 | 需要验证的差异 |
| --- | --- | --- | --- | --- |
| 1 Willow Creek | 道路连上不等于结构稳定 | 构件连接、三角形稳定；首次可控失败 | 学校花园收到幼苗，路线第一段亮起 | 训练结束后能独立完成，不只是照高亮点击 |
| 2 Fern Valley | 更长路径中每个节点如何接到支座 | 浮置/未接通支撑的证据 | 农场货物进入运输路线 | 不只复刻第一关加长；能指出连续路径 |
| 3 The high pass | 有限木料与钢材的角色取舍 | 高力构件、刚度/重量/强度 | 工坊收到机械，设施恢复小动效 | 至少两种材料安排有解释，不要求固定答案 |
| 4 Millwater Reach | 缆索放在何处才受拉 | slack 的位置和原因 | 磨坊修复配送完成 | 与“上弦全换缆索”形成可观察反例 |
| 5 Alder Ford | 如何真正接入固定中心桥墩 | 支座连接与有效跨径 | 诊所补给送达，地图显示中支点桥型 | 装饰性跨过桥墩与真实连接有可验证差异 |
| 6 Glen Echo | 没有桥墩时如何形成完整钢缆系统 | 支座路径、拉弦与压杆配合 | 救援无线电到达高地 | 不能直接粘贴第五关；不同几何/载荷不能声称受控对照 |
| 7 Foundry Bend | 重载下哪些杆件成为限制 | 首断、最大下落、受力比 | 铸造厂重件运达 | 轻载可行设计在该关暴露可解释限制；不只是堆钢 |
| 8 Riverbend Crossing | 综合选型且保持结构效率 | 综合诊断与可选证据解释 | 全路线开放、社区合景与个人工程回顾 | 至少两种综合可行解；结局与解锁/存档一致 |

每关内容卡另需记录：首次目标、可接受解族、一个典型错误、提示 1（提醒观察）/提示 2（说明原则）、参考桥何时解锁、成功文案、失败配送状态、结算截图。失败只表示该次配送待重试，不永久伤害社区，不扣尝试次数。地图“待连接/已连接”从完成存档推导，不能因重开桥或失败重测而错误熄灭。

反套路审计：把每个已通过方案尝试迁移到后续关卡，记录哪些靠缩放/换材料就可通过；若多关无需新判断，先调整提示与资源分配，再小步调整约束。目的不是禁止通用工程原理，而是让其迁移过程确实需要玩家判断。至少两个通过方案只能证明模型内多解，不保证多策略或最优。

## 7. 生产顺序：先锁质量，再做全量，绝不能把切片交付当成成品

### G0：现状基线与内容锁定

记录 git status 和已有脏改动；不回滚、不覆盖、不批量格式化。建立需求→文件→证据矩阵，读取并复跑现有测试作为新基线；记录失败是否预先存在。核对八关数值、资产、旧档样本和离线候选，确定本轮目标版本名。不得从过期 prompt 得出“没有工程”。

### G1：代表性纵向成品切片（内部质量门，不是 MVP 交付）

选择第 1 关和第 4 关：前者验证完整新手入口，后者验证缆索新决策及视觉解释。切片必须贯通菜单→故事/训练→任务→自由搭建→一次可理解失败→保留设计并修复→成功→社区变化→路线→退出刷新恢复。第 4 关同时贯通提示、参考桥和 Notebook 比较。

门槛：上述状态没有占位文案/坏链/临时素材；成功失败有不同主要行动；动画、声音、布局、输入完成到最终标准；关键路径截图和实操作记录齐全；数值及保存回归通过；独立验收者能按操作脚本完成。不得以“这两关已精美”停止工作或宣称完整小游戏。切片过门后必须复制质量标准到另外六关与最终结局。

### G2：八关全量内容生产

按第 5 节逐关完成内容卡、场景后果、短任务、提示、成功/失败结果、参考解释；补全地图、最终回顾和沙盒入口。每关有两条可行设计与至少一个有解释的失败例，记录库存/下落/断裂/载荷条件。第 5/8 关验证桥墩是固定支座，第 4/6 关验证缆索受力不是纯装饰。逐关留图和状态路径证据，不能只沿参考设计直通。

### G3：独立验收与修复循环

由 GPT-6.1 以独立审阅角色检查实现，不接受实施者自评为通过。先读需求矩阵和差异，再从干净存档及旧档分别验证；依照下节做自动和浏览器检查。输出每项 Pass/Fail/Not tested，失败给文件、复现步骤、预期、实际、优先级。GPT-5.6-sol 修复后重测失败项及受影响邻接路径；新缺陷重新进入清单。直到所有阻断关闭，或明确列为未完成，不能把未测算通过。

### G4：完整交付门

八关、训练、沙盒、结局均通过；无 P0/P1；现有自动测试和新增关键行为检查通过；实际离线包解压后从顶层入口重新通关关键路径；没有联网运行依赖、秘钥或缺失许可；附新版本运行指南、变更说明、测试记录、已知限制、素材来源。只提供本地成品与可审阅结果；公开发布、合并或外发不在本规划的自动授权范围。

## 8. 验收矩阵与缺陷优先级

自动验证依次运行 npm test、npm run test:browser、npm run test:engine、npm run test:input，按现有 scripts/package-release.py 生产新候选后 npm run test:package。改变关卡就重新生成对应数值审计；改变保存结构就验证 v0.3/v0.4/v0.5 样本迁移。测试不镜像实现，验证用户可见结果与关键不变量。

独立浏览器验收必须包含：

1. 冷启动、新档、跳过/重播故事、跳过/重做训练、继续旧档；每条入口都能回菜单。
2. 八关真实施工/测试/修改/成功，至少一个非参考方案；无脑空桥、断路、浮置框架、压缆索、材料超额、数值无法求解均有合理结果。
3. 第 5/8 关桥墩连接与不连接；第 6 关无桥墩；第 7 关重载；全线结局与地图持久状态。
4. 鼠标拖动、双击点式连接、键盘端点、触控；越界释放、缩放、窗口变小、后台切换、模态关闭；撤销/重做与重启后恢复。
5. Notebook 同设计重复运行、不同设计同条件、不同载荷、Self-weight 与 Crossing 区分、恢复历史、导出/导入、损坏文件、存储不可用。
6. 声音开启受浏览器手势限制时能恢复；静音保存/约定清楚；减弱动效、Canvas fallback、控制台错误与缺失资产。
7. 离线包迁移至新目录、断网打开、干净存储再试；不能只测开发目录。

P0：数据丢失/泄露、无法启动；P1：无法通关、关键导航/输入卡死、模型或条件混淆导致错误奖励、关键遮挡；P2：可绕开的信息/节奏/一致性问题；P3：纯装饰。P0/P1 必须关闭；影响“完整体验”的 P2 不能靠改叫低优先级放行。剩余 P2/P3 逐条写实际影响，不能笼统“后续优化”。

## 9. 观察指标：把待验证的判断变成可检查的问题

开发阶段记录确定性指标：八关可完成覆盖率、状态路径覆盖、旧档迁移通过率、离线资源失败数、未处理异常、输入取消后的残留手势数、实际支持的屏幕与设备。性能在指定浏览器/设备上记录帧时分布与最长停顿，不宣称普遍 60 fps。

后续真实试玩可先招募少量目标年龄学习者与成人，取得相应同意，以探索问题为目的，不声称统计有效性。观察冷启动到首次自主测试时长、需成人提示的位置、失败后能否指出证据、是否使用 Reference、跨关是否改变决策、在哪里退出、实际主线时长、能否用两案解释取舍。用行为记录＋短访谈，区分读不懂英文、操作不懂与结构概念不懂。

可暂设内部目标：首次训练后无需口头指挥完成“建造—测试—编辑”；失败后能找到下一动作；每关至少一次新决策；结局后能知道八关已经完成。这些尚非学生达标率。没有真人数据时，报告只能写“通过脚本验收/尚未真人验证”，不能编造完成率、满意度、课堂效果或学习增益。

## 10. 下一执行者的最高优先级任务

1. 先以当前八关已实现状态重写工作提示词，删除“尚未编程/先做 MVP”；把 G0–G4 和八关内容矩阵作为硬交付，不只要求“更好看”。
2. 先修首入任务、成功/失败主行动、路线后果与最终结局这条端到端体验；它们比追加关卡、换引擎或生成大批装饰图更接近成品缺口。
3. 用第 1/4 关成品切片锁统一标准，明确它只是内部门；继续完成其余六关、沙盒、旧档、离线包，才进入 6.1 独立验收。
4. 所有学习宣称严格沿用现有边界。提示与故事帮助玩家做工程判断，不能把教学术语、强制填表或通关章冒充学习成效。
5. 验收发现“体验不够完整”要落到可复现路径、玩家看到的信息和缺失后果，交给 5.6 修复；不要在模型之间循环空泛评价，也不要未经用户要求全面重做游戏。


## 11. 6.1 独立审查后的规划修订

本计划接受两项实质性自我修正。第一，原G1“成品标准”还可能被解释为只检查功能和入口：现明确要求逐状态截图/实际操作，覆盖任务、施工、测试、失败、成功、提示、Notebook和返回，检查字级/间距/层级、支座和力信息、场景后果及动效结束态；不能首页好看而结果页仍是临时拼接。视觉标准在切片前建立，不延后到全量末尾。

第二，切片需要内容、提示、比较和路线后果，不能依赖切片通过后才开始的全量生产：先定八关字段结构，切片生产第1/4关字段与最小路线/比较入口，全量阶段扩展其余六关。真实新手/学习者观察是待验证假设的必要证据，但招募缺失不无限期阻止本地软件交付；作者/代理实际完整操作及工程验收仍必须完成，G/L则按实际观察范围保留未验证，不宣称学习成效。

来源学习补记：主代理本轮实际取得并阅读MDA原论文（https://users.cs.northwestern.edu/~hunicke/MDA.pdf）与CMU学习原则（https://www.cmu.edu/teaching/principles/learning.html），本规划者依据其转交的要点核对：体验目标驱动规则与行为设计，游戏中的行为本身构成内容；有目标的练习、及时具体反馈、技能整合应用应进入循环。它们分别约束“八关是否产生不同判断”和“失败证据是否支持下一次行动”，不能用功能数量或术语映射取代。OpenAI models/prompting和Epic参考页本轮403，未读取，不引用为已学习资料。该记录区分实际阅读者，不伪称本规划者独立通读原文。

补充依赖规则：G0先有八关轻量schema/草案、现有数值审计可读与最小只读进度；切片数值修正证据按需提前，不受全量审计编号限制。若5.6连续两轮不能关闭同一阻断，或发现跨模块设计失配，6.1可定向接管修正，不重开全局；接管后由另一独立6.1复验，不能自改自批。


固定全屏证据清单：菜单、故事、训练（选择工具/连接/测试/完成）、首次任务、施工、测试运行与暂停、失败、成功、提示/参考、Notebook空态/两案/历史、路线部分/全完成、沙盒及换载荷、最终结局、设置/存储失败/导入确认。每项记录目标桌面尺寸截图，关键施工/训练/结果/Notebook/路线另记录平板与319px压力组合；不能以一张菜单图代替。截图核对统一深绿面板、橙色支座/主行动、材料纹理、力量非纯颜色标记、字级间距与遮挡；另留输入/动态操作记录，静态图不证明可交互。缺少适用状态证据记Not tested，不能默认通过。
