# 本轮资料学习、现场审查与迭代记录

日期：2026-11-05。范围：Riverbend v0.5 成熟化规划与提示词；不实施游戏升级、不生成新游戏交付包、不重跑历史游戏测试。

## 实际做过的学习

1. 阅读当前工作树的项目状态、README、package.json、教学设计、研究记录、测试记录及界面/状态/关卡相关源码。现有工程具备八关、Phaser、独立轴向求解器、Notebook、沙盒、保存迁移与离线包；旧 prompt 仍写尚未编程，与当前事实冲突。
2. 下载并实际读取 Hunicke、LeBlanc、Zubek 的 MDA 原论文（2004）：https://users.cs.northwestern.edu/~hunicke/MDA.pdf 。论文区分 mechanics、dynamics 和期望的情绪体验，主张从玩家体验反推机制，并通过定性/定量分析反复调优。对本项目的应用：把“有八关、有按钮”转为“玩家遇到什么决策、能观察什么、为何愿意重试、何时得到完成感”；Aesthetics 不等于画风。
3. 实际读取 CMU Eberly Center Learning Principles：https://www.cmu.edu/teaching/principles/learning.html 。其中关于目标导向练习、具体且及时的反馈、基础技能整合与何时应用的原则，支持本项目把构件编辑/受力观察/同条件改进串起来；这些原则不证明本游戏已产生学习增益。
4. 实际在本地游戏中检查菜单→八关选关→第一关施工→Task；看到约 319px 宽内嵌视图的顶栏右侧 About 被挤出，且从选关进入第一关后需主动点击 Task 才看到故事目标。检查只覆盖这些状态，未完整玩过八关，未做目标年龄用户研究。

## 本轮迭代的对象与方法

迭代的是外显的设计与实施规格，不是模型权重或永久训练。执行链为：读取事实→提出体验假设→核对实际界面→6.1 计划→5.6 细化→6.1 自我修订→独立 6.1 审查→按问题修订→记录未验证项。

核心修正方向：

- 从增添功能数量，改为全流程体验门禁；先锁第 1/4 关最终品质，再完成另外六关和结局，不能停在切片。
- 从“界面有功能”改为首入目标、成败主行动、可见社区后果、全线总结及所有状态的统一视觉层级。
- 从“测试绿灯即完成”改为工程验证、游戏性观察、教育证据三列独立结论；缺乏真人数据须如实记录。
- 从每次对旧 demo 追加补丁，改为保留/定向重构/淘汰的基线决策；必要时替换局部模块，避免框架整体重写转移目标。

具体自我修订和独立审查结果见 ACCEPTANCE_61_zh.md 与 INDEPENDENT_REVIEW_61_zh.md；若文件尚未生成，不应提前宣称已通过。
