## Pass / Fail / Not tested 的使用边界

- **文档 Pass**：规格一致、依赖可执行、证据定义清楚；绝非运行代码已实现。
- **文档 Fail**：本评审列出的依赖或退出条件矛盾，修订后须回查。
- **软件 Not tested**：本轮所有现有及未来游戏行为、输入、物理、存档、离线包、实际屏幕、性能均未重新执行。不得把PROJECT_STATUS历史通过复制成本轮通过。
- **游戏性 Not observed**：本评审未游玩，没有节奏、上手或乐趣结论。后续代理实际操作可报告路径与具体观察，不能冒充真人。
- **教育 Not observed**：没有学习者资料或真实学习行为证据；教学设计映射存在只证明设计意图。

软件最终交付与人类研究应分别报告：关键软件路径未测/有阻断不能称完整交付；真人研究缺失也不能被当成软件永远无法交付的理由。允许的软件完成声明须同时列出真人可用性、乐趣与学习成效尚未验证。
