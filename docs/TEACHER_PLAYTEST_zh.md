# Riverbend Bridge Engineer 1.4.0 教师课堂试玩指南

## 课堂目标

学生通过“预测 → 搭建 → 测试 → 观察 → 修改 → 同条件复测 → 解释”循环，讨论跨度、支座、拉力、压力、材料强度、长度引起的屈曲和成本权衡。游戏中的 12 cm、材料强度和价格是模型规则，不是现实桥梁安全标准。

## 三阶段课堂提示

进入关卡先看车辆、支座和跨度示意图，以及载荷、跨度、预算三个关键数字。Story, goal & rules 可展开完整叙事、约束和 Skill 标签。让学生先预测并测试；首次失败后的 What happened 可展开图示、角色解释，成功后可展开现实连接和多解提示。主动 Hint 可随时请求帮助，Task 会保留本次工作台会话已经释放的内容。

Notebook 在下一次测试前填写 Predict；测试开始后该预测保留，结果后填写 Claim/Evidence/Reasoning。每次测试独立编号，500ms自动保存，Previous test 可回看。不要用测试后的解释改写当时的预测。

## 建议流程（45–75 分钟）

1. **操作练习（5 分钟）**：第一次进入 Tabletop 会看到 Controls practice。让学生旋转视角、回到 Front view，用 Timber 连接两个金色节点，实际 Undo/Redo，再 Test，暂停一次并读颜色。也可从主菜单 Controls practice 重做。
2. **Tabletop（8–10 分钟）**：道路已铺好且锁定，学生先测试道路，再连接中部支撑。询问“哪里下落最多？为什么三角形改变了受力路径？”
3. **Willow Creek（10–15 分钟）**：只用 Timber，比较长压杆和较短的三角网格。让学生在 Notebook 里写一个可选预测，观察首断构件和最大下落。
4. **分支关卡（15–25 分钟）**：Clinic 让学生观察缆索松弛；Mill 让学生只替换首断构件的材料；Echo 比较两种可行结构；Finale 讨论不同支座怎样改变荷载路径。
5. **证据回顾（5–10 分钟）**：Notebook 中选择相同条件的两个测试，填写 claim/evidence/reasoning。引导学生写出限制：这是二维、铰接、轴向杆件模型，车辆是规定移动荷载。

## 观察证据

教师可记录学生是否能：

- 说明道路已经固定，主动把注意力放在支撑设计；
- 用共享端点解释“连通”，并知道相交但没有共同端点不算连接；
- 从颜色、拉压端标记、首断位置、道路下落和测试时长提出修改理由；
- 在相同跨度、载荷、支座、材料和预算下比较两次测试；
- 只修改一个成员的材料后复测，并承认一次失败或较短记录不能证明更优；
- 用数字证据解释一个选择，并指出模型限制。

星星、通关次数和文字长度不会自动代表掌握程度。

## 操作提醒

道路显示为 **Road ready · locked**（手机用锁图标），仍占预算并可能在仿真中下落。支持材料通过拖动或点击两个端点添加；Arrow keys + Enter 提供键盘路径。右拖或 Orbit view 旋转，Front view 回到可搭建立面，双指操作会取消当前连杆。Pause test 可冻结证据观察；打开 Notebook 或 Help 时仿真也会暂停。

## 交付与限制

入口是根目录或 `site/index.html`，均可离线 `file://` 打开。浏览器需要 WebGL 2。Notebook 是可选学习记录，不是评分系统。手机布局、真实浏览器触控事件及双指手势已自动验证；实体触屏设备、Firefox、Safari 和正式无障碍评估仍需单独进行。

手机上的操作提示在场景外显示，不覆盖支座。首次工坊会轻微转动一次并显示双指转动图示；触碰或选择 Front view 即停止。系统设置减少动态效果时不自动转动。手机 Hint 与地图入口位于 Help。详见 `MOBILE-UPDATE_zh.md`。

## 第二章与双语扩展（1.4.0）

可从主菜单独立进入五关进阶挑战，新增共同活载、船舶净空、岛上双跨及组合约束。建议另安排一节课，每次只比较同交通、同高度、同航道与同支座条件。所有关卡含实桥照片与模型差异；可按学习者需要切换中文或英文。流程、任务证据与模型限制见 [第二章说明](EXPANSION-v1.4_zh.md)。
